# 바로(BaLaw) 품질 지표 (v0.2)

`requirements.md`의 약속을 숫자로 재는 방법을 정의한다.
2단계 평가기는 이 문서를 그대로 구현한다.

v0.2 변경 (2026-11-25): 코드 점검 결과에 따라 M4·M6을 다시 정의하고, 측정 경로와 실행 규칙을 추가했다.

## 원칙

- **지표는 기획 문서의 주장과 짝을 이룬다.** 주장 없는 지표는 만들지 않는다.
- **정답이 있는 것은 규칙으로 잰다.** 정답이 없을 때만 LLM 판정을 쓰고, 표본은 사람이 다시 본다.
- **기준선을 먼저 잰다.** 목표값은 기준선을 본 뒤 확정한다. 아래 목표값 중 "기준선 후 확정"은 그 뜻이다.
- **정답 파일은 잠근다.** 평가 세트 파일의 sha256을 결과에 함께 기록해, 정답이 바뀌면 비교를 무효로 한다.
- **구조상 항상 만점인 지표는 두지 않는다.** 코드가 이미 보장하는 값을 재면 개선을 보여 줄 수 없다.

v0.1에서 바꾼 이유:

- **M4.** 죄목은 사용자가 화면에서 직접 고르고 그 값이 그대로 AI에 전달된다. 따라서 "죄목 판정 정확도"는 구조상 항상 100%다. 대신 AI가 실제로 판단하는 판례 검색용 키워드를 잰다.
- **M6.** 판례는 코드가 죄명 라벨로 걸러서 보여 주므로 "라벨 적중률"도 구조상 100%에 가깝다. 첫 실행에서 본 문제는 "사기" 라벨이 붙었지만 주된 사건이 마약·외환인 판례였으므로, 주된 죄명 기준으로 다시 정의한다.

## 측정 경로

필수 정보 채움 상태는 AI 서비스 응답에만 있고, 서버는 답변 문장만 넘긴다. 그래서 두 경로로 나눠 잰다.

| 경로 | 호출 대상 | 사례 수 | 재는 지표 |
|---|---|---|---|
| A. AI 직접 | AI 서비스 `/chat/init`, `/chat/send`, `/chat/compose` | 전체 | M1~M6, M8~M12 |
| B. 서버 경유 | 서버 API로 가입부터 DOCX 다운로드까지 | 10건 안팎 | M7, 그리고 서버 경유 응답 시간 |

DOCX의 죄명과 처벌 의사는 AI가 아니라 서버의 문서 양식이 넣으므로 M7은 경로 B로만 잰다.

**4단계 요구사항:** AI를 서버에 합친 뒤에도 평가기가 항목별 채움 상태를 읽을 수 있어야 한다. 평가 전용 응답 필드나 내부 API로 열어 둔다.

## 기록 장치

코드를 바꾸지 않고 M9~M11을 재기 위해, AI 서비스의 OpenAI 요청을 로컬 기록 장치를 거쳐 보낸다.

- AI 컨테이너에 `OPENAI_BASE_URL`만 지정하면 OpenAI SDK가 기록 장치로 요청을 보낸다.
- 기록 장치는 요청을 그대로 OpenAI에 전달하고, 모델·토큰·지연·요청 본문을 JSONL로 남긴다.
- 실패 주입 모드에서는 지정한 비율로 오류를 돌려준다 (M10).
- 로그에는 사례 서술이 들어가므로 git에서 제외한다.

## 평가 세트 구성 (40~60건)

| 묶음 | 건수 | 목적 |
|---|---|---|
| 사기 유형 5종 (전세, 투자 리딩방, 취업·알바, 보이스피싱, 중고거래) | 유형당 4~6 | M1~M4, M6~M8 |
| 모욕 (보류 판단용, 결정 0001) | 6~8 | M1, M2, M7, M8. 결과로 모욕의 정식 범위 포함 여부를 다시 결정 |
| 미지원 죄목 (횡령 최소 3건 포함, 폭행·명예훼손 등) | 5~8 | M4, M5 |
| 정보가 부족한 서술 | 5 | M2, M3 |
| 모호한 답변("기억 안 나요")이 섞인 대화 | 5 | M3, M12 |
| 인적정보가 서술에 섞인 사례 | 5 | M9 |

작성 원칙:

- 모든 인물·계좌·전화번호는 가상이다. 평가 세트는 공개 레포에 올라가고 OpenAI로 전송된다.
- 기존 기획 문서의 사기 시나리오 5종을 포함한다.
- 서비스 기획자가 직접 쓴 사례를 5건 이상 넣는다. 초안 작성자가 한 사람이면 서술이 정돈되어 실제 사용자 입력보다 쉬워지기 때문이다.

각 사례에는 정답으로 죄목, slot별 present/missing, 추가 질문에 대한 정해진 답, 초안에 들어가도 되는 사실 목록을 붙인다.
추가 질문에는 정해진 답을 돌려주는 모의 사용자로 대화를 자동 진행한다. AI 응답의 slot별 질문 횟수로 어떤 항목을 물었는지 알 수 있으므로 모의 사용자는 LLM 없이 규칙으로 동작한다.
