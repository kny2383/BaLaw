# 바로(BaLaw) 품질 지표 (초안 v0.1)

`requirements.md`의 약속을 숫자로 재는 방법을 정의한다.
2단계 평가기는 이 문서를 그대로 구현한다.

## 원칙

- **지표는 기획 문서의 주장과 짝을 이룬다.** 주장 없는 지표는 만들지 않는다.
- **정답이 있는 것은 규칙으로 잰다.** 정답이 없을 때만 LLM 판정을 쓰고, 표본은 사람이 다시 본다.
- **기준선을 먼저 잰다.** 목표값은 기준선을 본 뒤 확정한다. 아래 목표값 중 "기준선 후 확정"은 그 뜻이다.
- **정답 파일은 잠근다.** 평가 세트 파일의 sha256을 결과에 함께 기록해, 정답이 바뀌면 비교를 무효로 한다.

## 평가 세트 구성 (40~60건)

| 묶음 | 건수 | 목적 |
|---|---|---|
| 사기 유형 5종 (전세, 투자 리딩방, 취업·알바, 보이스피싱, 중고거래) | 유형당 4~6 | M1~M4, M7 |
| 모욕 (보류 판단용, 결정 0001) | 6~8 | M1, M2, M7, M8. 결과로 모욕의 정식 범위 포함 여부를 다시 결정 |
| 미지원 죄목 (횡령 최소 3건 포함, 폭행·명예훼손 등) | 5~8 | M5. 횡령 사례는 6단계 확장의 전후 비교 기준선으로도 쓴다 |
| 정보가 부족한 서술 | 5 | M2, M3 |
| 모호한 답변("기억 안 나요")이 섞인 대화 | 5 | M3, F14 |
| 인적정보가 서술에 섞인 사례 | 5 | M9 |

각 사례에는 정답으로 죄목, slot별 present/missing, 추가 질문에 대한 정해진 답, 초안에 들어가도 되는 사실 목록을 붙인다.
추가 질문에는 정해진 답을 돌려주는 모의 사용자로 대화를 자동 진행한다.

## 결과 기록 형식

실행마다 다음을 남긴다.

- 기준 커밋 해시, 날짜, 모델 이름, 프롬프트 판본
- 평가 세트 파일 sha256
- 지표별 값과 사례별 상세 결과
