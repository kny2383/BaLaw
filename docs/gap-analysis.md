## 가장 먼저 다룰 차이

1. **S05 식별정보 치환이 없다.** 최신 문서의 핵심 보안 주장이다. 사용자가 자유 서술에 쓴 이름·계좌번호가 그대로 OpenAI로 간다. 인적정보 폼 값은 AI로 보내지 않는 점은 맞다.
2. **S03 채팅 기록이 평문이다.** 채팅 메시지 내용이 암호화 없이 저장된다. 사건 서술 전체가 여기에 있어 가장 민감한 데이터다.
3. **F11 죄목 선택지와 AI 지원 범위가 어긋난다.** 고소장 작성 화면에서 사용자가 형사 죄목 24개 중 하나를 고르지만, AI는 사기·모욕만 지원한다. 사기·사이버사기·모욕을 뺀 21개는 모두 사기 양식으로 처리된다.
4. **S06 삭제 기준이 문서와 다르다.** 다운로드한 고소장만 삭제 대상이고, 매일 자정에 실행되어 실제로는 최대 48시간 남는다. 다운로드하지 않은 고소장과 채팅은 지워지지 않는다.
5. **S11 국외 이전 동의가 없다.** 처리방침에 OpenAI나 국외 이전 언급이 없고, 위탁 일반 조항만 있다.
6. **F17 few-shot 예시가 깨져 있다.** 예시 문장의 단어 대부분이 `{PERSON}`으로 치환돼 문체 예시 역할을 못 한다.

## 2단계 준비 중 발견한 문제

기록 장치의 실패 주입으로 확인했다 (2026-11-25, AI 직접 호출).

| 주입한 실패 | AI 응답 | 문제 |
|---|---|---|
| OpenAI 500 오류 | 200 정상 응답. 답변 앞에 `None` 출력 후 첫 질문("사건이 언제 발생했나요?")을 다시 함 | 사용자가 방금 한 답변이 버려지고, 내부 값이 화면에 노출됨. 로그는 한 줄만 남음 |
| 200이지만 JSON이 아닌 응답 | 위와 같음 | 로그가 전혀 남지 않음 |

두 경우 모두 지표 M10에서 1건씩 센다. 5단계 "실패 처리" 작업의 전후 비교 기준이다.

## 3단계 테스트 작성 중 발견한 문제

서버 테스트(`server/tests`)를 쓰면서 확인했다. 테스트는 지금 동작을 그대로 기록하고, 결함은 `xfail`로 표시해 고칠 때 통과로 바뀌게 했다.

| 항목 | 내용 | 다룰 단계 |
|---|---|---|
| 토큰 종류 구분 없음 | 액세스 토큰(30분)과 리프레시 토큰(7일)이 같은 형식이라 리프레시 토큰으로 API를 호출할 수 있고, 액세스 토큰으로 갱신도 된다. 리프레시 토큰이 새면 7일 동안 계정을 쓸 수 있다 | 3 (보안 수정 PR, `test_refresh_token_cannot_be_used_as_access_token`) |
| AI 오류 원문 노출 | AI 호출 실패 시 503 응답 본문에 내부 예외 문구(`AI 서비스 연결 실패: ...`)를 그대로 담아 보낸다. 내부 주소나 상태가 사용자에게 보일 수 있다 | 5 (실패 처리, 지표 M10) |
| AI 서비스에 인증 없음 | AI 서비스의 `/chat/*`는 세션 값만 알면 누구든 대화를 이어 가고 초안을 만들 수 있었다. 서버 뒤에만 두는 배포 구성이 유일한 보호였다. **조치함**: 서버와 AI가 같은 토큰(`BARO_AI_TOKEN`)을 쓰고, 운영 구성은 값이 없으면 뜨지 않는다 | 3 (조치) |
| 테스트용 공개 주소 | `/api/test/hello`, `/api/test/echo`가 인증 없이 운영에 열려 있다 | 3 (API 변경이라 따로) |
| 서버 이미지의 컴파일러 | `gcc`, `g++`, `build-essential`은 `chromadb` 빌드용으로 보이며, 제거 후에는 필요 없을 수 있다 | 4 (이미지 배포 전환 때) |
| 쓰지 않는 `python-multipart` | 서버에 설치돼 있지만 파일·폼 입력을 받는 API가 없다 | 4 (의존성 정리 때. 첨부 기능을 넣으면 그때 다시 쓴다) |
