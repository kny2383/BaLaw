# 로드맵

바로 리팩토링의 할 일과 진행 상황이다.

- 상태: ✅ 완료 (PR 병합) · 🟡 진행 중 · ⬜ 시작 전
- **완료 기준**: PR이 병합되고, 동작을 바꾼 항목은 평가기로 전후 숫자를 `eval/results/`에 남겼을 때 완료로 본다.
- 단계 번호(0~7)는 변경의 종류다. 실제로 하는 순서는 아래 "진행 순서"를 따른다.
- 구조 변경과 동작 변경은 한 PR에 섞지 않는다.
- 항목 ID는 `gap-analysis.md`(F·S·Q), 지표는 `metrics.md`(M1~M12)를 따른다.

## 진행 순서

1. **정보 추출 호출 개선** (5단계 중 먼저). 서비스 비용의 90%와 응답 시간 대부분이 이 호출이다. 먼저 고치면 이후 모든 평가가 싸지고, 구조 변경의 동일성 확인도 빨라진다.
2. **흔들림 측정과 AI API 동작 테스트** (2·3단계 남은 것). 구조 변경 전 안전망이다.
3. **LangGraph 이식** (4단계). 현재 흐름만 그대로 옮기고 숫자가 같은 범위인지 확인한다 (결정 0003).
4. **나머지 품질 개선** (5단계). 사용자 확인, 검증 후 재작성, 판례 검색, 식별정보 치환, 실패 처리.
5. **횡령 확장** (6단계), **사용성 테스트와 보류 세트 최종 측정** (7단계).

비용이 거의 들지 않는 일은 순서와 관계없이 틈틈이 한다: 모욕 재결정, 횡령 요구사항 정의서, M10 실패 주입 측정.

## 평가 예산 규칙

- 전체 개발 세트(38건)로 재는 것은 정보 추출 개선 전후, LangGraph 이식 전후, 마지막 최종 측정뿐이다.
- 그 밖의 개선은 10건 부분 세트(`--only`)로 재고, 결과 문서에 "부분 세트"라고 적는다.
- 실행 전에 예상 비용을 적고 승인을 받는다. 2026-11-26 기준 전체 1회는 약 5달러(서비스 3.2 + 판정 1.8)이고, 정보 추출 개선 뒤 다시 추정한다.
- 보류 세트(15건)는 마지막에 한 번만 연다.
