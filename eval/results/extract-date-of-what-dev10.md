# 추출 요약에 "무슨 일의 날짜인지"를 적게 함 (개발 세트 10건)

2026-11-27. 서비스 모델 `gpt-6.1-terra`, 판정 `gpt-6.1-sol`, 판정 기준 3판. 실행 `date-of-what-dev10` (대화·초안·검증·판정 전체, 1회). 보류 세트는 열지 않았다.

## 문제

`draft-date-dev10.md`에서 드러난 원인이다. 작성 요청에 실리는 날짜 요약이 "2026년 5월 12일이라는 날짜가 확인됩니다"처럼 날짜만 담고 있어, 작성 모델이 그 날짜를 어느 일에 붙일지 알 수 없었다.

## 바꾼 것

추출 지시문에 규칙 하나를 더했다: 날짜나 시간을 요약에 적을 때는 사용자가 그때 무슨 일이 있었다고 말했는지 함께 적는다. 사용자의 말과 방금 한 질문으로 알 수 없으면 "사건이 있었다고 하신 날"이라고만 적고 추측해 붙이지 않는다.

## 결과 1: 작성 요청에 실린 날짜 요약 (10건 전부)

| 사례 | 요약 |
|---|---|
| fraud-job-scam-04 | 돈을 송금하신 날은 2026년 2월 2일이라고 하셨습니다. |
| fraud-leading-room-01 | 돈을 보낸 날은 2026년 6월 3일, 6월 10일, 6월 24일이라고 하셨습니다. |
| insult-01 | 동창이 단체 카톡방에서 욕을 한 날은 2026년 10월 12일 밤이라고 하셨습니다. |
| sparse-03 | 돈을 넣으신 때는 올해 5월이라고 하셨습니다. |
| pii-02 | 2024년 2월에 계약하고 2026년 2월에 만기였다고 하셨으나, 구체적인 날짜는 말씀하지 않으셨습니다. |
| fraud-jeonse-04 | 사건이 있었다고 하신 날은 2026년 5월 12일입니다. |
| fraud-used-goods-03, fraud-voice-phishing-03, sparse-05 | 사건이 있었다고 하신 날은 11월 ○일 …이며, 연도는 확인되지 않았습니다. |
| vague-02 | 사건이 있었다고 하신 시기는 작년 말쯤이지만, 몇 월 며칠인지는 확인되지 않았습니다. |

5건은 무슨 일의 날짜인지를 적었고, 사용자가 날짜만 답한 5건은 "사건이 있었다고 하신 날"로 적었다. 이전 실행(`migrate-terra-dev10`)의 요약은 예를 들어 "2026년 5월 12일이라는 날짜가 확인됩니다"였다.

## 초안을 직접 읽은 것

- 날짜가 확인된 사례의 초안에 날짜가 모두 남아 있다 (연도 없는 "11월 ○일" 3건 포함).
- `fraud-jeonse-04`: "이 사건은 2026. 5. 12. 발생하였습니다. 피고소인은 … 계약을 체결하였고 …". 사용자가 한 말("사건이 5월 12일")과 같은 범위다.
- `pii-02`: "2024년 2월 … 계약을 체결하고 보증금 1억 2천만 원을 계좌이체하였습니다"가 그대로 나왔다. 이전 측정에서 지적된 문장과 같은 구조인데 이번 판정은 지적하지 않았다. **M1 0건에는 판정의 흔들림이 섞여 있다.**

## 한계

- 1회 측정이다. M1 0건을 이 변경의 효과로 단정하지 않는다. 반복 측정(흔들림)에서 다시 본다.
- 다시 물은 8회 가운데 2회가 날짜다 (`pii-02`는 "2024년 2월 계약"이라는 답에 며칠인지를 한 번 더 물었고 날짜 항목이 `missing`으로 남았다). 새 규칙이 날짜 판정을 더 엄격하게 만들었는지는 이 측정으로 가를 수 없다.
- `pii-02`는 날짜 항목이 `missing`인데 초안에 "2024년 2월"이 들어갔다. 사용자가 한 말이라 지어낸 것은 아니지만 "missing 항목은 쓰지 않는다"는 작성 규칙과 어긋난다.
