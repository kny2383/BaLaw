# 작성 프롬프트 수정의 효과 (compose-prompt-dev10)

같은 추출 결과로 초안 작성만 다시 했다. 대화와 정보 추출은 다시 하지 않았다.
원래 작성 요청 10건의 증거 메모는 모두 빈 목록(`[]`)이었고 다시 쓸 때도 같은 값을 넘겼다. 달라진 입력은 프롬프트뿐이다.

## 바꾼 것

지어낸 사실의 73%가 작성 단계에서 생긴다 (`m1-origin-dev10.md`). 작성 프롬프트에서 그것을 유도하는 지시를 고쳤다.

| 이전 지시 | 문제 | 바꾼 내용 |
|---|---|---|
| 처벌 요구 문장의 예시가 "재산적/정신적 피해가 극심하므로" | 예시를 그대로 따라 감정과 피해 정도를 쓴다 | 예시에서 피해 서술을 빼고, 넣지 말라고 적었다 |
| 범죄사실 맨 처음에 두 사람의 관계를 쓰라 | 관계를 모르면 지어낸다 ("평소 연락을 주고받던 사이") | 데이터에 없으면 쓰지 않는다 |
| 사기: 기망 → 착오 → 처분행위 → 손해에 각각 대응하는 사실을 드러내고 네 용어를 한 번씩 쓰라 | 단계를 채우려고 사실을 더한다 | 대응하는 사실이 있는 단계만 쓴다 |
| 증빙자료 여부를 고소이유에 쓰라 | "모르겠다"를 "없다"로 쓴다 | 가지고 있다고 말한 자료만 쓴다 |
| 가능한 자세히 서술하라 | 세부를 지어낸다 | 주어진 정보 안에서 쓰고, 정보가 적으면 짧게 쓴다 |
| (없음) | | 감정, 누가 요구·안내·거부했는지, 계좌 주인, 횟수, 환불 요청은 데이터에 있을 때만 쓴다. 누락·불명확 항목과 요약의 점검 문구는 옮기지 않는다 |

깨진 few-shot 예시(F17)는 건드리지 않았다.

## 읽은 것 (사람 1명, 1회)

- 감정과 피해 정도 서술은 사라졌다 (이전 12개). 판정이 "신뢰를 형성하였고", "반환을 기대하였습니다" 같은 심리 서술 2개를 잡았다.
- 남은 21개는 대부분 "모르겠다"고 답한 것의 단정(환불·회수 여부)과 세부 특정(시점, 판매 게시물, 송금 방식)이다.
- 초안이 약 30% 짧아졌다. 핵심 사실(일시, 금액, 상대, 발언, 송금 방식)은 읽어 본 초안들에 남아 있었으나 지표로 재지는 않았다.

## 한계

- 작성 호출의 응답 시간 중앙값(25.3초 → 30.2초)과 비용(0.052 → 0.068달러)이 늘었다. 프롬프트가 길어진 탓인지 호출 흔들림인지는 대조 실행이 없어 구분하지 못한다.
- 이전 프롬프트로 작성을 다시 돌린 대조 실행이 없다. 작성 호출의 흔들림(같은 프롬프트로 다시 썼을 때의 차이)과 프롬프트 효과가 섞여 있다.
- 판정 흔들림을 재지 않았다. 사례당 1~2개는 판정 차이로 봐야 한다 (`verify-rewrite-dev10.md`).
- 10건, 1회 실행이다. 프롬프트의 금지 항목은 이 10건이 속한 개발 세트의 분석에서 나왔다. 최종 숫자는 보류 세트로 다시 잰다.
- 사용자가 말한 사실이 초안에 남아 있는 비율은 재지 않았다.
