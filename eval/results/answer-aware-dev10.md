# 답이 질문에 대한 답이 됐는지를 보고 다시 물을지 정하기 (부분 세트 dev10)

같은 질문을 되풀이하는 문제(M12)를 다시 고친 결과다. 앞서 "한 번만 묻는다"로 고쳤다가(`ask-once-dev10.md`) 정보를 잃는 손실 때문에 기본값에서 뺐다.

## 무엇이 문제였나

사용자가 답한 뒤의 상황은 셋이고, 해야 할 일이 다르다.

| 상황 | 해야 할 일 | 상한 2 (처음 동작) | 상한 1 (`ask-once`) |
|---|---|---|---|
| 제대로 답함 | 다시 묻지 않는다 | 다시 물음 | 맞음 |
| 일부만 답하거나 엉뚱하게 답함 | 빠진 것만 한 번 더 묻는다 | 같은 문장으로 다시 물음 | 묻지 않아 정보를 잃음 |
| 모른다고 답함 | 다시 묻지 않는다 | 다시 물음 | 맞음 |

횟수로 정할 문제가 아니었다. 답이 질문에 대한 답이 됐는지를 봐야 한다.

원인은 구조에 있었다. 추출은 사용자의 말만 이어 붙여 받아서, 어떤 말이 어느 질문의 답인지 몰랐다. 그리고 매 턴 전체를 다시 판정해서, 이미 답한 항목이 "없음"으로 돌아가곤 했다.

## 바꾼 것

1. **방금 한 질문과 그 답을 짝지어 추출에 알려 준다.** 추출 요청 끝에 "[방금 한 질문과 답]"을 붙이고, 답이 질문이 묻는 내용을 담고 있으면 "있음", 일부만 답했으면 "불명확"과 빠진 것, 상관없는 말이면 "없음"으로 판정하게 했다.
2. **묻고 답을 받아 정해진 항목은 고정한다.** 답했거나("있음") 모른다고 한("모름") 항목은 다음 턴에 다시 판정해도 바꾸지 않고, 다시 묻지 않는다.
3. **두 번째로 물을 때는 문구를 바꾼다.** 처음 질문을 되풀이하지 않는다. 확인된 것과 빠진 것을 적은 문장에 이어 "빠진 내용만 알려 주세요. 모르시면 '모른다'고 답하셔도 됩니다"라고 묻는다. 세 번째는 없다.
4. **평가에 엉뚱하게 답하는 사용자를 넣었다** (`run_eval.py --stray-every N`). 정답에 있는 항목을 처음 묻는 질문 N번마다 한 번은 모의 사용자가 질문과 상관없는 말을 한다 ("그때 너무 당황해서 경황이 없었어요."). 서비스가 그 항목을 다시 물으면 그때 정답을 준다. 다시 물어 정답을 받았으면 "되찾음", 끝까지 묻지 않았으면 "잃음"이다.

같은 필수 항목을 묻는 횟수의 상한은 2 그대로다.

## 실행 조건

| 항목 | 처음 동작 | 상한 1 | 새 방식 |
|---|---|---|---|
| 실행 | `migrate-terra-dev10` | `ask-once-terra-dev10` | `answer-aware-stray3-dev10` |
| 엉뚱한 답 | 없음 | 없음 | 세 번에 한 번 (`--stray-every 3`) |
| 모델 | 모든 호출 `gpt-6.1-terra`, 판정 `gpt-6.1-sol` | 같음 | 같음 |
| 사례 | 부분 세트 dev10, 대화부터 판정까지 | 같음 | 같음 |
| 날짜 | 2026-11-27 | 같음 | 같음 |
| 비용 | 0.85달러 | 0.70달러 | 0.86달러 (+ 판정 0.10달러) |

**세 실행의 조건이 같지 않다.** 새 방식만 엉뚱한 답을 넣고 쟀다. 처음 동작과 상한 1은 엉뚱한 답을 넣어 재지 않았다.

## 결과

| 지표 | 처음 동작 | 상한 1 | 새 방식 (엉뚱한 답 18번 포함) |
|---|---|---|---|
| 엉뚱하게 답한 항목 / 다시 물어 되찾음 / 잃음 | 재지 않음 | 재지 않음 (구조상 다시 묻지 않는다) | 18 / 16 / 2 |
| 답을 받은 항목을 다시 물은 횟수 (M12) | 20 | 0 | 6 |
| 질문 수 평균 (M3) | 12.4 | 9.9 | 12.9 (엉뚱한 답 뒤의 16번을 빼면 11.3) |
| 필요한 질문 / 넘어간 필수 항목 (85개 중) | 60 / 25 | 56 / 29 | 61 / 24 |
| 첫 턴 재현율 / 정밀도 (M2) | 90.0% / 57.4% | 90.0% / 58.7% | 96.7% / 58.0% |
| 지어낸 사실 (M1), 판정 기준 2판 / 3판 | 0 / 3 | 1 / 2 | 0 / 2 |
| 초안 길이 (10건 합) | 3,667자 | 3,621자 | 3,477자 |
| 한 턴 대기 (p50) | 11.1초 | 11.2초 | 10.7초 |
| 서비스 비용 (10건) | 0.850달러 | 0.703달러 | 0.859달러 |

세 실행 모두 10건이 끝까지 진행됐고 오류는 0건이다.

### 남은 6번은 어떤 질문이었나

대화 기록을 읽었다. 6번 모두 사용자의 답이 실제로 일부만 담고 있었고, 서비스는 빠진 것을 짚어 물었다. 사례의 정답 자체가 모호하게 쓰인 것들이다 (모호한 답변, 정보가 부족한 서술 묶음).

| 사용자의 답 | 다시 물으며 짚은 것 |
|---|---|
| "부동산 앱 직거래 게시글을 보고 연락했고, 집 앞에서 계약서를 썼습니다." | 앱 이름과 집의 위치 |
| "4일에 보내고 5일 6일 계속 내일 보낸다고 하다가 7일부터 답장 안해요" | 송금 전의 과정 |
| "방장이 알려준 계좌요" | 계좌주가 누구인지 |
| "5월에 넣고 8월부터 출금이 안돼요" | 권유와 이체의 순서, 믿은 이유 |
| "몰라요 작년 말쯤?" | 월과 일 |
| "1000이요" | 금액의 단위 |

처음 동작에서 보이던 "답을 답으로 인정하지 않는" 되묻기(예: "신분증 사본을 보여 줬습니다"라는 답 뒤에 "믿게 된 이유는 언급되지 않았습니다")는 이 실행에서 찾지 못했다. 이 분류는 대화를 읽고 한 것이다.

### 잃은 2번

- "왜 그 말을 믿고 행동했나요?"에 "그때 너무 당황해서 경황이 없었어요."라고 답한 것. 서비스는 다시 묻지 않았다. 이 답은 그 질문의 답으로 읽을 여지가 있다.
- "그 말을 믿고 어떤 행동을 했나요?"에 같은 답을 한 것. 다시 묻지 않았다.

## 읽은 것

- **엉뚱한 답의 대부분을 되찾는다.** 18번 가운데 16번은 다시 물어 정답을 받았다. 상한 1이었다면 구조상 한 번도 다시 묻지 않는다.
- **되묻기는 20번에서 6번이 됐고, 남은 6번은 답이 실제로 모자랐던 경우다.**
- **질문 수는 줄지 않았다.** 엉뚱한 답 뒤의 재질문 16번을 빼도 11.3으로, 처음 동작(12.4)보다 조금 적은 정도다. 필요한 질문은 그대로다 (60 → 61).
- **초안은 달라지지 않았다.** 지어낸 사실과 초안 길이가 같은 범위다.

## 한계

- **조건이 다른 실행을 나란히 놓았다.** 처음 동작에 엉뚱한 답을 넣으면 몇 번을 되찾는지는 재지 않았다. 처음 동작도 두 번까지 묻기 때문에 상당수를 되찾았을 것이다. 이 변경의 효과로 말할 수 있는 것은 "되찾는 능력을 지키면서 되묻기를 줄였다"까지이고, 되찾는 능력이 늘었다는 것은 아니다.
- **새 방식을 엉뚱한 답 없이 재지 않았다.** 되묻기 6번은 엉뚱한 답이 섞인 대화에서 나온 숫자다.
- 구성마다 한 번 쟀다.
- **엉뚱한 답은 한 문장으로 고정이다.** 실제 사용자의 빗나간 답은 훨씬 다양하다. 일부만 답하는 경우는 따로 넣지 않았고, 사례의 정답이 원래 모호한 것들에서만 관찰했다.
- 고정한 항목은 사용자가 나중에 말을 바꿔도 다시 묻지 않는다.
- 추출 프롬프트가 바뀌어 프롬프트 판본이 바뀌었다 (`extract`).
