# 실패 주입 측정 (M10: 실패 은폐 건수)

LLM 호출이 실패했을 때 서비스의 응답이 그 사실을 드러내는지를 쟀다. 기록 장치가 호출 종류 하나에만 실패를 돌려주게 하고, 그 호출이 일어나는 단계의 응답을 본다 (`eval/fail_inject.py`).

## 실행 조건

| 항목 | 값 |
|---|---|
| 날짜 | 2026-11-27 |
| 사례 | 가상 사례 1건 (`fraud-jeonse-01`, 개발 세트) |
| 조합 | 호출 종류 6가지 × 실패 방식 2가지 = 12개, 조합당 1회 |
| 모델 | gpt-5-mini-2025-08-07 (주입 대상이 아닌 호출) |
| 실패 방식 `http` | 500 오류. 호출 계층이 두 번 다시 시도한 뒤에도 실패한다 (주입 3회) |
| 실패 방식 `garbage` | 200 응답이지만 내용이 한 문장이다: "죄송합니다. 지금은 답변할 수 없습니다." |
| 사용자 확인 단계 | 켜짐 (기본값) |
| 비용 | 첫 실행 0.110달러, 수정 뒤 다시 잰 3개 조합 0.027달러 |

판정:

- **드러남**: 실패가 주입된 단계의 응답이 실패를 알린다 (2xx가 아닌 상태, 판례 검색 `failed`, 판례의 `summarized: false`, 검증 상태 `unverified`·`rewrite_failed`).
- **은폐**: 실패가 주입됐는데 응답이 정상과 구분되지 않는다. M10에 센다.
- **미발생**: 그 호출이 일어나지 않아 주입되지 않았다.

은폐 2건은 같은 종류다. 글을 받는 호출이 형식에 맞지 않는 한 문장을 정상 출력으로 받아들였다. 구조화 출력을 쓰는 호출(정보 추출, 검증)은 같은 응답을 스키마 검사에서 걸러 냈다.

## 고친 것 (#64)

- 판례 키워드: 죄목 목록(291개)에 없는 출력은 키워드로 쓰지 않고 판례 검색 실패로 남긴다.
- 초안 작성: 고소이유가 빈 출력은 초안으로 돌려주지 않고 502로 알린다.

정상 출력을 잘못 거부하지 않는지는 저장된 과거 실행 기록으로 확인했다. 과거 판례 검색 201건의 키워드는 모두 목록에 있고, 과거 초안 196건은 모두 고소이유가 있다.

## 읽을 때 주의할 점

- **사례 하나, 조합당 한 번이다.** 실패 경로가 있는지를 본 것이고 비율을 잰 것이 아니다. "0"은 이 조합들에서 은폐가 없었다는 뜻이다.
- **재작성의 garbage 조합은 실제 서비스로 재지 못했다.** 이 경로는 테스트로만 확인돼 있다 (재작성 출력이 거절 문장이거나 고소이유가 빠지면 `rewrite_failed`).
- **재지 않은 실패 형태가 있다.** 형식은 맞지만 내용이 엉뚱한 출력, 응답이 매우 늦는 경우, 일부 호출만 확률적으로 실패하는 경우, 임베딩 호출의 실패는 넣지 않았다.
- **서버와 화면은 거치지 않았다.** AI 서비스의 응답만 봤다. 서버가 502를 사용자 안내로 바꾸는 것과 화면이 `summarized: false`를 표시하는 것은 각자의 테스트와 브라우저 확인으로 따로 봤다.
- 첫 실행의 표시에는 도구의 결함이 하나 있었다. 초안 길이를 응답의 틀린 자리에서 읽어 항상 0으로 나왔다. 판정에는 쓰이지 않는 값이고, 수정 뒤 실행부터 바로 나온다.
- 재작성 http 조합에서 판례 키워드가 "횡령"으로 나왔다 (다른 조합은 "사기"). 같은 서술에 대한 키워드가 실행마다 달라질 수 있다는 관찰이고, 이 측정의 대상은 아니다.
