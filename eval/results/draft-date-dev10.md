# 초안의 날짜를 다른 일에 붙이는 문제: 작성 지시문 규칙 (개발 세트 10건)

2026-11-27. 서비스 모델 `gpt-6.1-terra`, 판정 `gpt-6.1-sol`, 판정 기준 3판.

## 문제

사용자는 한 가지 일의 날짜만 말했는데(예: 보증금을 보낸 날), 초안이 그 날짜를 다른 일(계약, 상대의 말, 서류를 보여 준 일)에도 붙인다. 사용자가 말하지 않은 사실이 고소장에 들어간다.

## 바꾼 것

작성 지시문에 규칙 하나를 더했다: 날짜와 시간은 데이터가 그때 있었다고 밝힌 일에만 붙이고, 언제 있었는지 데이터에 없는 일은 날짜 없이 쓴다.

## 방법

`migrate-terra-dev10`의 대화 결과(추출 결과)를 그대로 두고 초안만 다시 썼다 (`recompose.py`). 고치기 전 지시문으로 한 번(`date-before`), 고친 지시문으로 한 번(`date-after`). 검증·재작성 단계는 거치지 않은 초안이다. 각 1회.

## 결과

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| M1 지어낸 사실 (건) | 3 | 1 |
| M1 지적이 있는 사례 | 3 | 1 |
| M8 단정 표현 | 0 | 0 |

고치기 전의 3건은 모두 날짜를 다른 일에 붙인 종류다. 초안을 직접 읽은 결과:

| 사례 | 고친 뒤 | 판단 |
|---|---|---|
| sparse-03 | 수익 보장 발언에서 날짜가 빠지고 이체에만 붙음 | 고쳐짐 |
| fraud-jeonse-04 | "2026. 5. 12. 발생한 이 사건에서 … 소개하였고 … 이체하였습니다" | 판정은 통과했으나 날짜를 사건 전체에 건 표현이라 애매함 |
| pii-02 | "2024. 2. 계약을 체결하고, 보증금을 계좌이체" | 남음 |

날짜가 확인된 사례에서 날짜가 빠진 초안은 없다. `vague-02`에서 "작년 말경"이 빠졌는데, 날짜 항목이 `missing`이라 쓰지 않는 것이 맞다.

## 한계와 남은 원인

- 각 1회라서 3건과 1건의 차이는 실행 간 흔들림 안에 들 수 있다.
- 원인은 작성 앞 단계에 있다. 작성 요청에 실리는 날짜 요약은 "2026년 5월 12일이라는 날짜가 확인됩니다"처럼 날짜만 있고 **무슨 일의 날짜인지**가 없다. 작성 모델은 규칙을 받아도 어디에 붙일지 알 수 없다. 추출 요약이 무슨 일의 날짜인지 함께 적게 하는 수정을 다음 PR에서 한다.
